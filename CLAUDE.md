# Legal-RAG — Claude Code context (keep this file short)

Hallucination-resistant Legal RAG system. Full detail lives in `/docs`, not here — read `docs/architecture.md` first, then the relevant `docs/phases/phase-NN-*.md` before touching that phase's code. Don't re-derive or re-paste that content here or back to the user; reference file/section instead.

**One-liner:** legal Q&A over retrieved documents, where every claim in the answer is checked against its source before being shown, and ships with a structured proof trace.

**Core pipeline:** ingest → SAC chunk → embed → LanceDB (hybrid vector+FTS, local, file-based) → rerank → citation-forced generation → 6-layer verification chain (V1–V6) → abstain-or-answer → API + multi-page UI. Details: `docs/architecture.md`.

**Build order:** one phase at a time, per `docs/phases/`. Don't start phase N+1 until phase N has passing tests.

**Rules:**
- No fabricated metrics/results — anything quoted must come from a logged run in `/experiments`.
- Keep LLM + embedding backends behind thin swappable interfaces.
- Plain commit messages describing what changed — no AI/Claude attribution, co-author lines, or "Generated by"/session links in commits on this repo. History should read as if the project owner made every commit themselves.
- Commit and push every 2-3 logical changes as you go — don't batch a whole phase (or more) into one giant commit/push at the end. Small, frequent, plainly-described commits.
- Don't inflate this file — extend `/docs` instead.

**Hard-won lessons (don't relearn these):**
- **Diagnose before fixing.** When something looks broken (an abstention, an empty result), measure the actual pipeline stage first (e.g. hit `/retrieve` directly, log what context reached `/query`) before changing code. Several real bugs here (shallow candidate pool, token budget starving the answer, a whitespace bug in a source id) were only found this way — guessing would have "fixed" the wrong thing.
- **An abstention is not automatically a bug.** This system is supposed to refuse to answer general/definitional questions ("what is an NDA") that its indexed documents don't actually define — that's the hallucination-reduction feature working, not a failure. Only escalate an abstention as a bug if the question is answerable from a specific clause that's actually indexed.
- **Free-tier LLM APIs (Gemini) return transient 503s under load.** Retry with real backoff (several attempts, seconds-scale pacing), not a shallow 2-3 try loop — this has bitten real batch runs.
- **The real corpus lives in `data/corpus/` (gitignored, not sample fixtures).** It's CUAD/MAUD-style real contracts (NDAs, mergers), not statutes — SAC's Act/Chapter/Section parser won't match them, so they go through fallback paragraph chunking. That's expected.
- **This sandbox (if you're running in the remote/web environment) blocks most external domains**, including the Hugging Face model download `sentence-transformers` needs — embedding-dependent tests will skip here, not fail, and that's not a bug. They run for real on a machine with normal internet.
